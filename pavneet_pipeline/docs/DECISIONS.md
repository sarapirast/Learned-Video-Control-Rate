# Decisions

Format: **D<n> (date) — decision.** Why. Runbook said / alternative considered.

- **D1 (2026-10-29) — Paths: project `/scratch1/pbanga/ee599`, work dirs `/scratch1/pbanga/rcwork` (x265) and `/scratch1/pbanga/rcwork_x264`.** Runbook's `/scratch/$USER` does not exist on CARC (it is `/scratch1`). Scratch has no backups -> code + reports are periodically copied to `/home1/pbanga/ee599_backup`.
- **D2 — Conda env by `--prefix` on scratch, Python 3.12, latest available package versions (recorded in `LEARNINGS.md` once built).** Runbook's pins (Python 3.14.4, torch 2.14.1, numpy 2.5.4, pandas 3.1.0) are unverified; exact pins don't matter because this is a new implementation, not a bit-exact rerun.
- **D3 — `PATH` to x265/x264 set inside job scripts, not `~/.bashrc`; job scripts do `module purge` and never `source ~/.bashrc`.** Cluster policy: batch jobs must not rely on login env; editing `.bashrc` is risky on HPC.
- **D4 — Parallelism across nodes.** Runbook allows one node per script. Since the code is new, encode-heavy stages (infos, hindsight search, evaluation) are sharded over GOPs as SLURM job arrays, and PPO runs one job per (k, seed). Per-job training recipe (RC_ENVS=14, n_steps=64) is unchanged, so this is not a scale-up.
- **D5 — Every source is centre-cropped to 16:9 and scaled to 320x180 (lanczos) at download time, keeping all source frames (no fps change).** CIF is 4:3; cropping avoids aspect distortion. Big sources (1080p, films) are streamed into the downscaler and never stored at full size (saves ~40 GB of scratch).
- **D6 — Data sources (runbook's "12 pilot clips from GitHub" have no stated source, so they are replaced):** 31 Xiph CIF + 11 Xiph 720p + 19 Xiph 1080p, 5 films (BBB, Elephants Dream, Sintel trailer from Xiph y4m masters; Tears of Steel 720p and Sintel 1080p (720p only offered as .zip) from download.blender.org), YouTube UGC 360P originals, first 10 per category (name order) over 13 categories (~125 clips, ~22 GB transfer). Total transfer ≈ 40 GB as approved.
- **D7 — STATIC pattern = offsets (−6, −3, +3) for [I frame, P1–P9, P10–P29].** The runbook gives the three numbers but not the segment boundaries; split at frame 10 is assumed. `static_pattern` study refits pattern and split on training data and reports how far the assumed one is from the fitted one.
- **D8 — Action = per-frame QP offset in {−3..+3} on top of base QP (30 or 38) + STATIC.** Runbook does not state the action set.
- **D9 — Bits per frame are counted from the Annex-B bitstream for both encoders** (VCL NAL units + VPS/SPS/PPS attributed to the next frame; SEI and AUD excluded so x264's version-string SEI doesn't inflate the IDR frame). Runbook used x265's CSV for x265; `codec_check` cross-checks the two.
- **D10 — Quality metric: per-frame 6:1:1 weighted YUV PSNR, GOP PSNR = mean of per-frame values; decoded with ffmpeg.** Runbook says "PSNR" without specifying.
- **D11 — Encoder preset `fast` for all forced-QP and own-RC encodes; `ultrafast` for the first-pass features.** Runbook doesn't name a preset; `fast` keeps the 1M+ search encodes affordable. Single-threaded (`--frame-threads 1 --no-wpp --pools none` / `--threads 1`) for determinism.
- **D12 — GOP windows:** evenly spaced, non-overlapping 30-frame windows per clip: 8 per Xiph/UGC clip, 60–90 per film (skipping the first 2 s and last 10 s of films for titles/credits). Plus **spliced GOPs** (2–3 segments from different sources of the same split, cut frames recorded): 120 train / 40 val / 60 test. They give ground truth for the scene-detector study and make cuts common enough to learn from.
- **D13 — Splits by source:** each Xiph/UGC clip goes to train/val/test by a hash of its name (60/20/20); films are split whole: BBB + Elephants Dream → train, Tears of Steel → val, Sintel (film + trailer) → test. Deterministic, so both encoders get identical GOPs.
- **D14 — Budget and score:** budget = bits of the encoder's *own* `--qp` mode (I frame gets the encoder's default ipratio offset) at QP 30 / 38; the scoring curve is the same mode at QP 18–50. Penalised score = saving − 2 × (% over budget); % GOPs over budget always reported. The runbook says "penalised" without the weight; 2 makes 1 % overspend cost more than the ~1 % saving it can buy.
- **D15 — Offline data cap:** per (GOP, budget) the 24 best + 24 random logged search plans become CQL/BC/IQL trajectories (runbook's `LOG_CAP` idea, applied to every k so the k curve is not confounded by data size).
- **D16 — Restructured pipeline.** The runbook's 13 historical steps (rl_suggestions, rl_matrix, seeds, switch, overshoot, lagr, cutspec, expand, extend, expand2) were the laptop project's chronological history; here they become phases: `infos` → `scenes` → `search` → `baselines` → `rl` (one job per run) → `analysis` → `codecs`. Every runbook study keeps an equivalent: switch, overshoot, lagr/PID-lagr, cutspec, static_pattern, own RC, k curve; `expand2_report.md` and `codecs_report.md` are still produced.
- **D17 — Strict lookahead.** At lookahead k the observation contains only frames t..t+k; all summary features (window cost mean, scene share, distance to next cut) are computed over visible frames only. Frame position and the STATIC offsets of unseen frames are known (they are not lookahead).
- **D18 — Rules as lookahead baselines.** Besides the runbook's causal rule, a deterministic *lookahead rule* (cost-share allocation over the visible window) is evaluated at every k, so the RL k curve has a non-learned counterpart; a *scene rule* adds extra bits on detected cut frames.
- **D19 — MPC (model-based) method:** per-frame bits/PSNR MLP trained on search logs + CEM receding-horizon planning; maximises predicted mean PSNR under the budget (never uses the constant-QP curve, which a causal controller cannot know).
- **D20 — MPC plans against a safety margin.** With full information the bits model is unbiased (actual/predicted GOP bits: median 1.03, p10–p90 0.88–1.19), yet v1 MPC was over budget on 60–80 % of GOPs: CEM pushes PSNR right up to the predicted budget and selects plans the model underestimates. v2 plans against `margin × budget`, margin ∈ {0.80 … 1.0} chosen per run on val (sweep stored in `eval.pkl["margin_sweep"]`). v1 results kept in `results_rl_v1/`.
- **D21 — DQN update rate.** v1 used SB3 `train_freq=4` with 14 vec-envs → ~1 000 gradient steps for 60 k transitions (and the score fell as ε decayed). v2: `train_freq=1, gradient_steps=N_ENVS` (one gradient step per transition), lr 1e-4, exploration_fraction 0.5. Env-step budget unchanged (60 k) so the method comparison stays equal-data.
- **D22 — Common-yardstick scores skip extrapolation.** In `codecs.py`, x264 points whose PSNR lies outside x265's QP 18–50 curve are left out of "score common"/"saving common" (counted in an `out of ref range` column); log-bits extrapolation there gave −1379 / −3e11.
- **D23 — Extensions matching the external extend_report.md.** (a) `experiments/breakdown.py`: no new encodes; per-group results (scene cut / natural / spliced / stable / gradual), their headline metric (saving clipped ±50 %, >1 % over) next to ours, bootstrap CIs, win/loss analysis vs the k=5 lookahead rule. (b) New runs (`runs/extend.txt`, 28 per encoder): `--extra fb` (achieved PSNR last/mean, bit-prediction error last/mean, frames since cut; online env decodes every step), `--extra sum` (fb + window summary replacing the raw lookahead slots) at k=5 and k=29; `cql_a2c` (A2C warm-started from CQL like CQL->PPO); `cql_dqn` (DQN Q-net initialised from the CQL Q-function, ε 0.1→0.02); `ensemble` (mean action probabilities of the 3 CQL->PPO k=5 seeds, no training); `gate` (per-frame PPO gate on the k=0 observation choosing the k=0 or k=5 CQL->PPO policy, charged λ ∈ {1, 3} score points per GOP fully at k=5); `lagr_ft`/`pid_ft` (continue the k=5 CQL->PPO policy 40 k steps under the Lagrangian/PID reward with cut GOPs sampled 4×). gate / *_ft / ensemble depend on the finished CQL->PPO k0/k5 runs.
- **D24 — MPC margin grid 0.60–1.0 (step 0.05).** Every x265 v2 MPC run chose 0.80, the lowest margin offered, so the optimum lay outside the grid. v2 results kept in results_rl_v2/.
- **D25 — Multi-GOP rate control (#2, `rclib/clipenv.py`, `experiments/clip_rl.py`).** Episode = 8 IDR GOPs (same-clip time-ordered runs, or mixed streams from different clips) under one budget = s × bits at constant QP q0 (train: q0 ∈ 24–44, s ∈ U(0.8, 1.25); eval: q0 ∈ {30, 38}, s ∈ {0.85, 1.0, 1.18}), so the QP that meets the budget is unknown. Each step picks one GOP's constant QP as an offset −6..+6 on a causal model QP (first-pass model, 5.5 QP per doubling fitted on train, online calibration). GOP outcomes come from the real constant-QP curves in infos, so there are no encodes; frame-level control is not included. Stream PSNR is pooled over MSE: with a mean of dB values the hindsight plan reached +36 % by putting bits into cheap static GOPs. Baselines: hand rule (offset 0), best constant QP in hindsight, and the hindsight per-GOP plan (Lagrangian sweep + greedy). The hindsight plan often runs below budget, because the score (saving at equal PSNR) does not reward using the budget, and its offsets saturate at +6. Methods: BC (imitates the hindsight plan), PPO from scratch (2 M steps), BC→PPO; lookahead L ∈ {0, 2} GOPs; 3 seeds.
- **D26 — Model-based pre-training (#3, `rclib/mbenv.py`, methods `mb`/`mb_ppo`).** `mb` = CQL distillation, then 1 M PPO steps inside the learned per-frame model from the k=5 MPC run of the same seed. `mb_ppo` = `mb`, then 40 k PPO steps on real encodes. Compare with CQL→PPO (60 k real steps). The model is used only for differences from the GOP's real STATIC encode. Scoring the model's raw PSNR on the real curve was unusable (mean error −196 points). With anchoring, on val the model scores a CQL→PPO policy at 11.3 vs 12.9 real (corr 0.60, MAE 13.7 points per GOP). The injected noise (GOP bias sd 0.10, frame sd 0.05 in log2 bits) is kept small because the model's own error already acts as noise. k ∈ {0, 5}, 3 seeds.
- **D27 — Constrained RL vs imitation (#1, `experiments/constraint.py`).** No new runs. BC vs CQL→PPO vs Lagrangian/PID (from the offline start, and as fine-tunes) vs the ensemble at k = 0/5/10, with overshoot statistics and paired bootstrap CIs. Reports in `results/<codec>/constraint_report.md`.
