# Data v1 (320x180)

**Status: frozen 2026-11-03.** Do not change the clips, splits or labels; changes go into a new version.

Generated by `scripts/data_readme.py` on 2026-11-09. Every number below comes from the data files; rerun the script after any change. Rules and the evidence behind them: `docs/clip-selection.md`.

## Overview

- 109 clips, 31342 frames, 1042 full 30-frame GOPs (partial GOPs at clip ends are not used).
- Format: `clips/<clip_id>.y4m`, 8-bit 4:2:0, 320x180, native frame rate, limited range.
- Splits are by **group** (a film, a shoot or a YouTube uploader), never by clip or GOP. Resample by `group` for confidence intervals.
- Files: `manifest.csv` (one row per clip: source, crop, colour handling, fps, MD5), `gops.csv` (one row per GOP: label, cut frames), `features/siti.csv` (per frame), `cuts/` (cut signals and frames).

- 182 cut frames in total. A GOP is `cut` if a cut falls inside it (not on its first frame); 7 GOPs have a cut exactly on their first frame and are not labelled `cut`.
- Detectors: luma-histogram change (64 bins, > 0.35) and ffmpeg `scdet` (> 10). Every frame where only one fired, or where the rule rejected a detection, was reviewed by eye: 270 review verdicts for clips in v1 (cut 79, gradual 62, no_cut 128, unsure 1).

## Known caveats

- The histogram cut detector re-implements the pilot's (threshold 0.35); its bin count still needs checking against the pilot code.
- Dissolve detection is untested; dissolves found so far came from the visual reviews.
- Lanczos scaling rings at sharp edges: 0.02-0.24% of pixels fall outside 16-235 (left unclipped).
- Test cut GOPs are concentrated in two films; see the group breakdown above.
