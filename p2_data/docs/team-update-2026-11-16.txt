Everything below is on data v1, scored with the dB metric (dPSNR_B - 0.17 dB per 1 % over budget). "*" = 95 %

1. HEADLINE: a learned per-GOP controller now beats final4 on test

R3 = residual PPO on top of final4 (QP offsets -6..+6 per frame), actor initialised by imitating the hindsight
search (centred BC), lookahead k5, 180k PPO steps. Fresh seeds 3-5, single sealed test pass (approved 11-16):

  R3 - final4, k5, test:   x264 +0.066 [+0.022, +0.106] *    x265 +0.162 [+0.085, +0.243] *
  every seed positive (x264 +0.03..+0.11, x265 +0.16..+0.17)
  x265 vs final4 + per-frame shift (the second x265 baseline): +0.074 [+0.041, +0.105] *
  vs CQL->PPO 540k: +0.13 / +0.20 *;  vs encoder ABR+VBV at a tuned margin: +1.05 / +0.71 *
  360k steps adds nothing over 180k

Where it comes from: better quality for the bits, and far fewer overshoots (over budget on 24 % / 21 % of
episodes vs final4's 55 %). The gain is on stable GOPs (+0.07 / +0.18 *); cut/gradual GOPs are positive but not
significant. The imitation start is what makes it work: the same setup started from scratch (control R2c) is
0.13 dB worse. Imitation alone (no RL) fails: it drifts once it runs. R3 was tested only at k5.


2. THE PROTOCOL THIS ROUND (why these numbers should hold up)

- Every experiment had its pass/fail rule written before results (exp_next/*/PREREG*.md); post-hoc changes are
  labelled. Selection on a held-out fold of 8 train clips, confirmation on val, test touched once at the end.
- Paired comparisons on identical GOPs and budgets, CIs by resampling whole clips.
- Hindsight checks: e.g. the budget "level" is clip-level hindsight under v1's clip-mean budgets, so it is not
  used anywhere; a level flag (o[2]) that was in every learner's input since the pilot was checked: removing it or
  replacing it with a causal stand-in changes evaluation scores by at most 0.02 dB.

5. PAVNEET'S LIVE-STREAM WORK (D38-D42, email 11-15) -- strongest RL-wins story in the project

Very nice result (ppo_v2 vs the buffer rule vbv2: +0.44 / +0.35, robust across every sweep; il_ppo best). It also
lines up with our R3: start from a good controller, imitate the hindsight solution, refine with RL. Before it goes
in the report, a few checks that would make it much harder to challenge:
1. Grid edges in vbv2: several tuned values look like grid limits (rmargin 0.9 in all four settings, psi 1.0
   x265-sim, beta 1.0 x264-4G, alpha 1.0 in two settings). Exp 7 shows an edge optimum can hide most of RL's edge.
   Could you send the grid ranges and widen any edge?
2. MPC with the true network model does no better than vbv2 (closes -1 % to -8 % of the oracle gap); its 2-knob
   grid (gamma, H) is probably too small, so "RL beats MPC" is weak as it stands.
3. Test was reported in every round D38-D42 while the design changed (D39 baseline rebuild, D42 variants). Tuning
   was on val, but the write-up should say test was seen repeatedly (or reserve a fresh sealed check).
4. Same-clip vs mixed: the n = 8 test set includes 100 spliced streams, where most of D34's gain was. Could you
   split ppo_v2 - vbv2 by same-clip / mixed?
5. Metric: luma PSNR plus a stall term, so these numbers stay separate from the YUV 6:1:1 per-GOP numbers.
