EE599 RL rate control - (i) additional experiments, (ii) test2 add-on
Aayush, status 2026-11-18. Every number comes from a results file (paths given per item).

Score: dPSNR_B - 0.17 dB per 1 % over budget (0 = constant QP spending exactly the budget).
Differences are paired per (GOP, budget level); 95 % CI = clip bootstrap; "*" = CI excludes 0.
final4 = our frozen causal controller (the baseline every learner must beat). k = lookahead in frames.
Each experiment had a written pre-registration (PREREG) with a pass/fail rule before it ran; all on val
unless stated.

=====================================================================================================
TL;DR
=====================================================================================================
- Standalone learners (BC, CQL->PPO, Lagrangian PPO) never beat our causal controller final4. Most of
  their loss is in landing the budget, not in how they allocate bits (Exp 1).
- What worked: a residual on final4, priced at the metric's own overshoot rate (Exp 3), started from a
  BC actor and fine-tuned with PPO (R3). BC alone loses (closed-loop drift); the PPO step turns it
  into a win (+0.20 to +0.36 dB over BC).
- R3 beats final4 at k5 on both encoders, on v1 test (x264 +0.067 *, x265 +0.163 *) and on test2,
  a fresh set of 93 unseen UGC clips (x264 +0.044 *, x265 +0.187 *). test2 was frozen in advance and
  gated by exact parity with v1.
- The win comes mostly from overshooting less: R3 is over budget on 20-25 % of episodes vs ~55 % for
  final4.
- x265: gains almost everywhere (classes, categories, k2 and k5). x264: small gain, stable GOPs only.
- No gain from: handoff (Exp 2), per-context settings (Exp 6), RL at stream level vs a retuned rule
  (Exp 7), longer training (360k), lookahead beyond k5.
- test2 add-on: built a second test set end to end (93 new YouTube-UGC clips, 12 categories, one clip
  per uploader, none shared with v1; same decode / labels / curves / budgets pipeline, cut labels by
  the v1 two-reviewer protocol, kappa 0.62). Nothing trained or refit on it; pre-registration frozen
  before any score; the test2 code path reproduces every stored v1 row exactly on 3 v1 clips.
- test2 confirms the v1 story: the primary replicates on both encoders, RL over BC holds at k2 and k5
  (+0.20 to +0.36 *), R3 beats every baseline (final4 + shift, CQL->PPO, ABR), and pooled v1 test +
  test2 gives x264 +0.049 *, x265 +0.181 *.

Exp 1 - where does final4 lose to the hindsight search?             results_v1/next/exp1/
  Q: score decomposition and how much headroom a learner could take.
  - Allocation headroom (search - final4) = +0.37 dB [+0.27, +0.49].
  - Causal methods differ from final4 almost only in spend error (mean |err| final4 3.1 %, CQL->PPO
    4.7 %, residual 6.1 %). final4 loses ~0.3 dB to landing and ~0.35 dB to allocation.
  - The local R-D slope is 0.036-0.064 dB per 1 %, so the best over-budget rate is 21-37 %;
    final4 goes over on 43-65 %.
  -> Motivated the residual design and pricing the overshoot at the metric's own rate.

Exp 2 - handoff: learner for the first frames, final4 for the last m    results_v1/next/exp2/
  - FAIL (non-inferiority at m = 10): hybrid - final4 -0.052 [-0.146, +0.056].
  - Longer handoffs under-spend: final4's one-slope rate model, calibrated at the learner's QPs,
    over-predicts the remaining bits. -> final4 should plan every frame; learner adds on top.

Exp 3 - residual on final4 priced at the metric (lambda 0.17 vs 0.34)   results_v1/next/exp3/report.md

=====================================================================================================
(ii) TEST2 ADD-ON: frozen models on a fresh held-out set (11-17)
=====================================================================================================
Why: v1 test was used once, but models and baselines were developed on v1. test2 checks whether the
result replicates on clips nobody has seen. Evaluation only - nothing trained, refit or tuned on test2.

Data (exp_next/test2/select_t2.py; data/t2/320x180)
  - 93 new YouTube-UGC clips, 12 categories (~8 each), one clip per uploader, no uploader shared with
    v1; 320x180, 30-frame GOPs -> 930 GOPs; 860 scored in 88 clips after the flat-GOP rule.
  - Same pipeline as v1: decode, first-pass bits/stats, constant-QP curves QP 18-50 both encoders,
    budgets from the v1-TRAIN fit, previous-GOP base estimate, final4 / final3 controller runs.
  - Cut labels with the v1 protocol: two detectors, blind two-reviewer round 1 (80 % exact,
    90 % cut vs not-cut, kappa 0.62; v1 was 0.64), settlement, round-2 check. Scored GOPs:
    788 stable, 69 cut, 3 gradual.

Safeguards
  - PREREG.md frozen BEFORE any test2 score was computed (primary, secondaries, decision rules).
  - Parity gate: 3 v1 test clips run through the test2 code path must reproduce the stored v1 rows
    exactly. PASSED: every data stage, R3 324/324, CQL->PPO 648/648, final4/final3, ABR 224,
    shift 108/108, PSNR-cap correction.
  - Code changes behind a P2_DATA switch (default = v1), snapshotted in git first.

Takeaways
  - The R3 result is not a v1 artefact: it holds on a new, all-UGC set with a different content mix.
  - RL over imitation is the most robust effect (+0.20 to +0.36 dB, both encoders, both k).
  - x265: gains everywhere (classes, categories, k2 and k5). x264: small gain, stable GOPs only.
  - No deviation from the pre-registration.

Caveats: final4 and the ABR margins were tuned on v1 val; test2 is UGC only (no Xiph / Blender /
