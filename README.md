# Learned Video Rate Control under a Bit Budget

USC EE599 (Reinforcement Learning) team project. An RL policy chooses the quantisation parameter (QP) of every
frame inside a real video encoder (x264 and x265), so that each group of pictures (GOP) fits a hard bit budget
at the best possible quality.

**Research question:** how much of an offline hindsight search's gain can a single-encode policy capture, and how
does that change with the lookahead k (the number of future frames it may see, from 0 = strictly causal to the
whole GOP)? Results are split by GOPs with scene cuts vs stable GOPs.

## Setting (shared by all streams)

- **Episode:** one GOP of 30 frames (an IDR frame + 29 P frames), coded by a real encoder; every bit count and PSNR
  comes from an actual encode.
- **Encoders (P1's frozen settings):** x264 0.165 and x265 4.1, preset medium, IPPP, keyint 30, scene-cut
  detection / AQ / mb-tree (cutree) / psy off, one thread. Per-frame QPs are forced through a qpfile.
- **Score:** % bits saved at equal PSNR against the GOP's own constant-QP curve, minus 2 points per 1% over budget.
  Bits are slice bits (headers reported separately); PSNR is the YUV 6:1:1 average over frames.
- **Models are trained per encoder:** first-pass bits, bit counts and the score all come from that encoder.

## Data

Video and results are not in git (see `.gitignore`). On USC CARC the dataset lives at:

- **Shared, read-only copy for the team:** `/project2/rashidin_1753/aayushso/ee599_data/v1/320x180/`

Every data file is regenerated by the scripts in `p2_data/`.

## Conventions

- Only code, configs and docs go in git; never video, encodes or results.
- Every number in a report comes from a results file produced by a script.
- Splits are by source group (film, shoot or uploader), never by GOP. Spliced clips are train-only.
- CARC jobs go through `sbatch` (see each stream's `jobs/` or `tools/`).
